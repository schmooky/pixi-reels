<ConceptPart title="Hold & Win" lede="How a Hold & Win round runs, and how to drive the board from your game client.">

Hold & Win, also sold as Lock & Respin or Hold & Spin, is a feature where
coins land, stick, and refill a respin counter until the board fills or the
respins run out. pixi-reels ships it as a built-in board:

```ts
import { HoldAndWinBuilder } from 'pixi-reels';
```

The demos above each show one technique. This part explains how the board
works as a whole and how a game client drives it.

<a id="the-mental-model"></a>

## How the board is built

A Hold & Win board is a grid of cells that spin independently. The engine
spins in columns, each a `ReelSet`, but the mechanic works in cells. So each
cell is its own 1x1 reel set, and `HoldAndWinBuilder` lays out the grid and
runs the round across them.

The board does not know what a coin is worth. A coin is an opaque record:

```ts
{ cell: { reel, cell }, id: 'coin', data: /* anything you want */ }
```

The `id` picks the registered symbol art. The `data` belongs to you and can
hold values, jackpot tiers, multipliers or collector flags. The board never
reads it. Adders, doublers, collectors and flights to a meter are game logic
you write on top of the board, using these:

| API | What it gives you |
|---|---|
| `board.events` | each step of the round, with the coin payload |
| `board.symbolAt(cell)` | the live symbol instance, so you can call your own symbol's methods |
| `board.cellCenter(cell)` / `board.cellBounds(cell)` | exact pixel geometry for flights and trails |

With that split, a new Hold & Win variant is mostly game code and the board
stays the same.

<a id="the-lifecycle"></a>

## The round

The board is a three-state machine. `board.phase` reports where it is:
`'idle'`, `'active'` or `'spinning'`.

<Timeline
  beats={['idle', 'active', 'spinning', 'active']}
  edges={[
    { after: 0, label: 'enter(seed)' },
    { after: 1, label: 'respin(hits)' },
    { after: 2, label: 'cells land' },
  ]}
  spans={[{ from: 1, to: 3, label: 'respins left, board not full', loop: true }]}
/>

<Timeline
  beats={['spinning', 'feature:end', 'idle']}
  edges={[{ after: 0, label: 'board fills OR respins hit 0' }]}
/>

1. `enter(seed)` seeds the board with the trigger coins. They lock at once,
   without a spin, and the respin counter arms. The board goes from idle to
   active.
2. `respin(hits)` spins each free cell. The cells named in `hits` land their
   coins and the others land blank. The board goes from active to spinning
   and back. If a coin landed in this wave the counter resets to full. If
   nothing landed it goes down by one.
3. The feature ends when the board fills or the counter reaches zero, and
   the board returns to idle. Then you collect.

<a id="what-one-respin-fires"></a>

### Events in one respin

Events come in a fixed order. Cells land in stagger order, so the landing
and lock events arrive one at a time:

<a id="wiring-it-to-your-game-client"></a>

## Driving it from your game client

The board runs the animation of each round. You own the loop and the source
of results, which can be an RGS, a mock server or an RNG. The driver is
short:

```ts
const board = new HoldAndWinBuilder<{ value: number }>()
  .grid(5, 3)
  .cellSize(72, { gap: 4 })
  .symbols((r) => r.register('coin', CoinSymbol, COIN_OPTS))
  .weights({ coin: 1, empty: 4 })   // how often coins flash past during the spin
  .respins(3)
  .ticker(app.ticker)               // required: drives every cell's reel
  .build();

app.stage.addChild(board.container);

// React to the round however your game presents it: HUD, sounds, flights.
board.events.on('coin:locked', ({ coin, locked, capacity }) => {
  hud.total += coin.data?.value ?? 0;     // you own the value; the board does not
  hud.text = `${locked} / ${capacity}`;
});

// 1. trigger
board.enter(await server.triggerCoins());

// 2. the respin loop: one round per iteration, you pace it
while (true) {
  const round = await server.nextRound(board.freeCells);   // your result source
  const result = await board.respin(round.hits);           // the board animates the wave
  if (result.done) break;                                  // full or out of respins
  // anything between rounds (celebrate, delay, play a teaser) happens here
}

// 3. collect: release the coins and fly them wherever you like
for (const coin of board.lockedCoins) flyToMeter(board.cellCenter(coin.cell), coin.data?.value ?? 0);
board.release(board.lockedCoins.map((c) => c.cell));
```

`respin()` resolves only after the whole wave has landed and the counter has
been updated, so the loop reads top to bottom.

For a [skip button](/mechanics/hold-and-win/#hold-and-win-skip), call
`board.skip()`. It slams each cell that is still spinning. The landing, lock
and feature-end events still fire, so the rest of your code does not change.
The quicken form, `board.skip({ mode: 'quicken' })`, lands the cells instead
of cutting them. Each spinning cell drops its minimum spin time, so the wave
lands together, and each cell still spins its symbol in and bounces. Add
`speed: 'turbo'` to land it on turbo, or make quicken the board's default
with `skipMode('quicken')` on the builder.

<a id="events-reference"></a>

## Events

Each event carries your `TData` on its coins.

| Event | Payload | Fires when |
|---|---|---|
| `feature:enter` | `{ seed, respins }` | `enter()` seeds the board |
| `respin:start` | `{ round, respinsLeft, spinning }` | a wave begins |
| `cell:landed` | `{ cell, coin }` (`coin: null` on a miss) | each cell settles, in stagger order |
| `coin:locked` | `{ coin, locked, capacity }` | a hit cell locks |
| `cells:activated` | `{ cells, capacity }` | `activate()` woke dormant cells; `capacity` is the new full-board count |
| `speed:changed` | `{ name, previous }` | `setSpeed()` moved every cell to another profile |
| `respins:changed` | `{ value, reason }` | the counter changed (`seed`, `hit-reset` or `miss`) |
| `respin:end` | `{ round, hits, respinsLeft }` | the wave finishes |
| `board:full` | `{ coins }` | the last free cell locks |
| `feature:end` | `{ coins, rounds, full }` | the feature is over and the board is idle |
| `coin:released` | `{ coin, remaining }` | `release()` removed a coin (the collect moment) |
| `feature:reset` | `{ clearedCoins }` | `reset()` hard-cleared the board |
| `feature:skip` | `{ inFlight, mode, speed?, payload? }` | `skip()` freed the in-flight cells, placed (`'slam'`) or landing through their stop (`'quicken'`). `speed` and `payload` are the press's options as given |

`release()` means "collect this coin" and fires `coin:released` once per
coin. `reset()` is a hard clear back to idle and fires a single
`feature:reset`, so a HUD that counts down on collect does not tick on a
reset.

`setSymbolAt(cell, id, data)` rewrites a locked coin in place, for example
a coin becoming MINI and then MAJOR, and keeps the board's ledger correct.
It throws on a free cell. New tracked coins are placed only by `enter` and
`respin`.

<a id="rectangular-cells-the-lock-animation-dormant-cells"></a>

## Other builder options

Production boards often need more than the square default. These builder
options cover cell shape, the lock animation and cells that start outside
the feature:

```ts
const board = new HoldAndWinBuilder()
  .grid(5, 3)
  // art is 202x170: a seam between columns, rows touching
  .cellSize({ width: 101, height: 85 }, { columnGap: 6, rowGap: 0 })
  // 'win' (default) plays playWin() on every lock; 'landing' plays the
  // symbol's playLanding() settle instead; 'none' plays nothing
  .lockAnimation('landing')
  // built, drawn as `sealed`, but outside the feature until activate()
  .inactive(row(0).concat(row(4)), 'sealed')
  ...
```

With `'landing'` or `'none'` the celebration is up to you.
`await board.playWin()` pulses each locked coin, and
`board.playWin(cells)` pulses a subset. Call it when the game decides, usually on `board:full` or after
`feature:end`.

Some coins start their own landing beat when they land, such as a Spine coin
with `autoPlayLanding` or a sprite that reports its settle through
`trackLanding`. They keep it. `'win'` waits for that beat before the
celebration, and `'landing'` does not play it a second time. The mode can
also be a function of the coin that locked, so a collector celebrates while
plain coins only settle:

```ts
.lockAnimation((coin) => coin.id === 'collector' ? 'win' : 'landing')
```

`board.activate(cells)` wakes dormant cells between waves. They show the
empty symbol, join the next respin and count toward `isFull` from then on.
`reset()` seals them again. The rectangular cells, landing only and growing
board demos above show each of these.

<a id="draw-order-between-cells"></a>

## Draw order between cells

Each cell is its own reel set, so a coin's `zIndex` only sorts it against
its own cell's buffers. Art that the engine lifts above a cell's mask at rest
(`unmask: true`) renders in one layer above all cells, in attach order,
which is column by column. As a result the next column covers the overflow
of a lower coin. `cellZIndex` makes that layer sortable, and the board asks
it for each cell's order on each place and landing:

```ts
.cellZIndex(({ cell, symbolId, cols }) =>
  (symbolId === 'grand' ? 1000 : 0) + cell.cell * cols + cell.reel)
```

`board.liftedLayer` is that layer, for an effect that has to sit between the
cells and their lifted art. `symbolZIndex(resolver)` is the per-symbol form
from `ReelSetBuilder`, applied inside each cell. See
[big symbols](/mechanics/big-symbols/#zindex-layering).

<a id="speeds-board-wide"></a>

## Speeds

Each cell is its own reel set with its own `SpeedManager`. The board
registers speeds in all of them and switches all of them together:

```ts
const board = new HoldAndWinBuilder()
  .speeds({ normal: NORMAL, turbo: TURBO, superTurbo: SUPER_TURBO })
  ...
board.setSpeed('turbo');            // every cell, at once; fires speed:changed
board.addSpeed('cinematic', slow);  // one more, after build
```

Cells land in a diagonal wave, and the wave's step is the active profile's
`stopDelay`. On a reel set that value is the time between reels stopping. On
a board it is the time between steps of the wave. Each cell spins
`(reel + cell) * stopDelay` ms on top of the profile's `minimumSpinTime`, so
NORMAL's 140 ms steps the wave and TURBO's 0 lands all cells together.
`.stagger(fn)` replaces the shape of the wave. It receives the speed's name
and profile:

```ts
.stagger((reel, cell, speed, profile) => reel * profile.stopDelay) // column by column
.stagger((reel) => reel * 120)                                     // fixed, whatever the speed
```

The rule is the same as for `reelSet.setSpeed()`. A cell already in flight
finishes on the profile it started with, and the next wave runs on the new
one. To cut a wave in progress on a turbo press, call `board.skip()`. To
land it on turbo instead, call `board.skip({ mode: 'quicken', speed: 'turbo' })`.
Each speed name also gets a `name:tension` variant that the board uses for
an anticipating wave.

<a id="own-the-board"></a>

## When the board does not fit

pixi-reels ships boards in two layers:

- `BoardGrid` is the primitive. It is a grid of cells that each spin
  independently. It knows geometry, instances and spinning, and nothing about
  coins, locks, respins or value.
- `HoldAndWinBoard` is one board built entirely on the primitive's public
  API. It adds the rules for locking, respins and collecting.

If the built-in board does not do what your game needs, these are the
options, from least to most work:

1. Configure it. Stagger, respins, weights, anticipation and cell chrome are
   all builder options. Most games stop here.
2. Build on the primitive. If your feature is not lock and respin at all,
   for example pick and reveal, cluster collect or a scratch card, skip
   `HoldAndWinBuilder` and use `BoardGrid` directly. The
   [board grid reveal demo](/mechanics/layers/#board-grid-reveal) is a board
   on the primitive that is not Hold & Win.
3. Fork the board. For lock and respin with different rules, copy
   `HoldAndWinBoard` and `HoldAndWinState` into your project and point their
   imports at `pixi-reels`. Everything they use (`BoardGrid`, `EventEmitter`,
   the `Hw*` types, `cellKey`, `HwEffect`) is public API, so the copy stays
   on supported ground. Then rewrite the reducer. The rule that a hit resets
   the respins and the rule that a full board ends the feature both live in
   `HoldAndWinState`.

The board never reads your `data` and has no paytable. What a coin means is
decided in your code, and the board only moves the reels.
