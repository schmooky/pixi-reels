`ReelSet` extends `PIXI.Container`. Construct it with [`ReelSetBuilder`](/reference/api-builder/), add it to your stage, then drive it with the methods below.

Every method on this page is synchronous unless its return type is `Promise`. Most errors throw synchronously at the call site, in the same stack frame you wrote. The exceptions are cancellation: `spin()` rejects on its watchdog or `SpinOptions.signal`, and `nudge()` rejects with an `AbortError`.

## Spin

| Method | Signature | Notes |
|---|---|---|
| `spin` | `(options?: SpinOptions) => Promise<SpinResult>` | Start a spin. Resolves on `spin:complete`. Pass `{ holdReels: [...] }` to freeze columns, or `{ mode: 'cascade' }` to override the builder default for one call. |
| `setResult` | `(symbols: ColumnTarget[]) => void` | Set the target grid. Triggers the stop sequence. One `ColumnTarget` per reel: `{ visible, bufferStart?, bufferEnd? }`. |
| `setAnticipation` | `(reelIndices: number[], options?) => void` | Mark reels that should enter `ANTICIPATION` before stopping. Held indices are dropped without an error. Options: `stagger`, `slowdown`, `duration`, and `protect` (`'once'` \| `'stepwise'` \| `'always'`), which stops a skip press from hiding the tease. |
| `setStopDelays` | `(delays: number[]) => void` | One delay in ms per reel, overriding `reelIndex * speed.stopDelay` for the current spin. Persists across `refill()` calls in the same round. |
| `setMinimumSpinTime` | `(ms: number \| number[] \| null) => void` | Override the `SpinPhase` floor the profile's single `minimumSpinTime` imposes on every reel. Pass an array for per-reel values. This lets one reel land below the shared floor without slamming the whole set. Persists until cleared with `null`. |
| `setDropOrder` | `(order: 'ltr' \| 'rtl' \| 'all' \| number[] \| null, stepMs?: number) => void` | Wraps `setStopDelays`. Common patterns: `'ltr'` (initial cascade reveal), `'all'` (the usual refill), `[0,0,200,200,400]` (V-shape). A named order counts over the reels that spin, so it covers reels added later and orders an `expand()` step by place. |
| `skipSpin` | `(options?: SkipOptions) => void` | The round-aware press. The first press boosts speed (standard mode) or flags refills to auto-slam (cascade mode); later presses free the rest. `options.mode` is what the press does to the reels it frees. `'slam'` places them (the default unless `builder.skipMode()` says otherwise). `'quicken'` asks each for its landing sooner: the tease ends, the delay is cut, and the spin-out and bounce still play, on `options.speed` if one is named. `payload` reaches every phase's `onSkip(ctx)`, rides on `skip:requested` / `skip:completed` beside the `speed` profile, and ends up in `SpinResult.skipContext`. Throws before `setResult()`. Between two `expand()` steps, when nothing spins, the press carries to the next step instead of being dropped. |
| `requestSkip` | `(options?: SkipOptions) => void` | The safe press before `setResult()`. Queues until the result arrives, then presses with the same `options` as `skipSpin`. Bypasses the round-side-effect machine. Between two `expand()` steps it queues for the next step, as `skipSpin()` does there. Either mode is a skip: `skipStage` advances, `wasSkipped` is `true`, `SpinResult.skipMode` says which. A quicken press treats the reels it already quickened as down and walks on to the next group; a slam press cuts them. In cascade mode a quicken slams and warns once with code `quicken-cascade`. |
| `slamStop` | `(options?: { reels?: number[] \| except?: number[] }) => void` | An unconditional slam, whatever the set's `skipMode`. No boost, no auto-slam flag, no tease protection. With `reels` or `except` (not both) it lands only those reels, and every other reel keeps running to a natural landing. Throws before `setResult()`, like `skipSpin()`; a spin whose result will never come is aborted through `spin({ signal })`. |
| `skipNudge` | `(reel?: number) => void` | Fast-forward an in-flight `nudge()` to its landed state. `skipSpin` and `slamStop` land a spin; this lands a nudge. |
| `skipStage` | `readonly 0 \| 1 \| 2` | `0` until the first press of the round, `2` after the press that ended it, in either mode. `1` means a press freed the reels around a protected tease and left the tease running, so the button should stay live; the next press ends it. Decided before the press lands anything, so a `spin:complete` listener already sees `2`. Drive UI labels from this, but gate on `isSpinning` first. The stage is scoped to the round and only resets on the next `spin()`, so an `'always'` round (where no press ever reaches `2`) leaves it parked at `1` through the idle window. |
| `isSpinning` | `readonly boolean` | `true` between `spin:start` and `spin:complete`. In a cascade round it goes true and false once per refill. See the [cascades guide](/mechanics/cascade/#concept). |

```ts
const result = await reelSet.spin({ holdReels: [0, 4] });
console.log(result.symbols);       // final visible grid
console.log(result.wasSkipped);    // true if slam ended the spin
```

## Cascade (tumble)

Available when the builder was configured with `.tumble({...})`. See the [cascades guide](/mechanics/cascade/#concept) for the mental model.

| Method | Signature | Notes |
|---|---|---|
| `refill` | `(opts: RefillOptions) => Promise<RefillResult>` | Moment B: place and drop in the survivors and the new symbols. There is no fall and no wait for a result. The default `mode: 'combined'` animates survivors and new symbols together. `mode: 'gravity-then-drop'` splits it into a survivor-settle stage, a hold, then a drop-in stage; see [Two-stage refill](#two-stage-refill) below. Pass `signal: AbortSignal` to cancel mid-refill. Throws without `.tumble()`. The result exposes `winnersRefilled`, `finalGrid`, `wasSkipped`, `duration`. |
| `destroySymbols` | `(cells: ReadonlyArray<Cell>, opts?: DestroySymbolsOptions) => Promise<void>` | Calls each symbol's `playDestroy()` (the default is a brief scale and fade implode). Lifts zIndex so the destroy is not clipped. Optional `delay`, `zIndex`, `dim`, `signal`. |
| `runCascade` | `(opts: RunCascadeOptions) => Promise<RunCascadeResult>` | Runs the whole cascade in one call: detect, destroy, pause, refill, repeat. Pass `signal: AbortSignal` to cancel from the caller. Use it for a slam press between refills, because `reelSet.skipSpin()` does nothing while the engine is idle. The two-stage options apply per chain here: `mode` is called `refillMode`, and `gravityHold` is a function of `info` that builds the promise; `gravityHoldMs` and `onGravityComplete` keep their names. See [Two-stage refill](#two-stage-refill). Per-stage progress comes as `cascade:chain:start` and `cascade:chain:end`; the awaited promise resolves when the chain is over. |

```ts
import type { Cell, RunCascadeResult } from 'pixi-reels';

// Moment A: fall, wait, drop in.
const spinDone = reelSet.spin({ mode: 'cascade' });
reelSet.setResult(await server.spin());
await spinDone;

// Moment B: N refills until no more wins.
const summary: RunCascadeResult = await reelSet.runCascade({
  detectWinners: (grid): Cell[] => myClusterDetector(grid),
  nextGrid:      (_, winners) => server.cascade(winners),
  onCascade:     ({ chain }) => ui.bumpMultiplier(chain),
});
console.log(summary.chainLength, summary.totalWinners, summary.wasSkipped);
```

### Types

| Type | Shape | Notes |
|---|---|---|
| `Cell` | `{ reel: number; cell: number }` | A grid cell. `reel` is the column, `cell` is the visible cell index. Used by `destroySymbols`, `runCascade`'s `detectWinners`, and `refill({ winners })`. |
| `DestroySymbolsOptions` | `{ delay?, zIndex?, dim?, signal? }` | Defaults: zero delay, zIndex `1000`, no viewport dim. `delay` accepts a number or a `(cell, index) => number` function for a per-cell stagger. Pass `zIndex: null` to suppress the bump, for when another presenter already drove the visual. `signal` aborts mid-destroy and snaps cells to their destroyed pose. |
| `RunCascadeOptions` | `{ detectWinners, nextGrid, presentWinners?, onCascade?, pauseAfterDestroyMs?, maxChain?, destroyOptions?, signal?, refillMode?, gravityHoldMs?, gravityHold?, onGravityComplete? }` | `detectWinners` and `nextGrid` carry the game rules. Everything else is timing, cancellation or gravity feel. Both callbacks may be `async`. `nextGrid` must return `ColumnTarget[]`; a plain `string[][]` is not accepted anywhere in the API, so wrap it with `grid.map((visible) => ({ visible }))`. Defaults: `pauseAfterDestroyMs: 250`, `maxChain: 32`, `refillMode: 'combined'`, `gravityHoldMs: 250`. The `onCascade` payload is `{ chain, winners, currentGrid }`, the same grid `cascade:chain:start` reported. Here `gravityHold` is a function, `(info: { chain, winners }) => Promise<void>`, called once per chain stage; the promise it returns gates that stage's drop-in. `onGravityComplete` is `(info) => void \| Promise<void>` and fires after both hold sources resolve, before the drop-in starts. |
| `RunCascadeResult` | `{ chainLength, totalWinners, finalGrid, wasSkipped }` | Returned by `runCascade`. `chainLength === 0` means no wins on the initial grid (no refill ran). |

```ts
// Cancellation via AbortSignal: the right shape for "player tapped slam
// between refills" (reelSet.skipSpin() is a no-op when the engine is idle).
const controller = new AbortController();
skipBtn.addEventListener('click', () => controller.abort());

const { wasSkipped } = await reelSet.runCascade({
  detectWinners, nextGrid,
  signal: controller.signal,
});
```

`runCascade` also listens to `skip:requested`, so `reelSet.skipSpin()` during a refill works. Only the AbortSignal handles a press in the idle window between refills.

### Two-stage refill

`refill({ mode: 'gravity-then-drop' })` splits the refill in two. Survivors slide first, then there is a hold across the board for anticipation visuals, then the new symbols enter. This is how Reactoonz, Gates of Olympus and Mummyland refill. `'combined'`, the default, is how Sweet Bonanza and Sugar Rush refill.

```ts
// Single refill: pass the promise directly.
await reelSet.refill({
  winners,
  grid: nextGrid,
  mode: 'gravity-then-drop',
  gravityHoldMs: 150,                 // minimum wall-clock floor (default 250)
  gravityHold: multiplierRoll.done,   // OR an already-in-flight animation
  onGravityComplete: () => sfx.peak(),// awaitable hook between stages
});
```

`gravityHoldMs` and `gravityHold` run in parallel under `Promise.all`, and the drop-in waits for whichever finishes last. Pass both when you want a wall-clock floor under an animation that might be fast. `onGravityComplete` runs after both, so it can read the state after the hold.

```ts
// Per cascade: runCascade calls the builder once per chain stage.
await reelSet.runCascade({
  detectWinners, nextGrid,
  refillMode:    'gravity-then-drop',
  gravityHoldMs: 150,
  gravityHold:   ({ chain }) => multiplier.bumpTo(chain + 1).done,
});
```

The events `cascade:gravity:start`, `cascade:gravity:symbol` and `cascade:gravity:end` fire only in this mode. See the [events reference](/reference/api-events/#cascade-tumble).

If your `gravityHold` promise never resolves, the engine waits forever and the cascade hangs. There is no built-in timeout. If your animation source can stall (an animation library error, missed user input, a hung XHR), wrap it in your own `Promise.race([yourPromise, timeoutReject])` before passing it in, or rely on `gravityHoldMs` alone. A rejection in `gravityHold`, or a throw from `onGravityComplete`, does not reject the `refill()` or `runCascade()` call. The engine catches it, emits `cascade:gravity:error`, logs it and slams to recover, so the awaited promise still resolves. A `try` block never sees it; subscribe to `cascade:gravity:error`.

## Growing the board

Add reels after the last one and take them away again, at rest. `expand()` is the "infinity reels" chain built on them; see the [recipes](/mechanics/infinity-reels/).

| Method | Signature | Notes |
|---|---|---|
| `addReels` | `(count: number, options?: AddReelsOptions) => readonly Reel[]` | Append `count` reels, laid out, masked and pooled like the built ones; `reelSet.reels` grows in place and the viewport with it. `options.visibleCells` is one number or one per reel (default the last reel's count, or `maxCells` on MultiWays), and `options.initialFrame` is one `ColumnTarget` per reel. A reel may not be taller than the tallest one. The reels one call adds join a `setReelGroups()` layout as one trailing group, take a `setCurve()` curve, and land a pending `setShape()` at the shape they were added with. Fires `reels:added`. |
| `removeReels` | `(count?: number) => void` | Destroy the last `count` reels; without `count`, every reel added since `build()`, a no-op when there are none. Their symbols go back to the pool (an animation still playing on one stops with it), pins on them expire (`'explicit'`), a spotlight hides, groups drop them, and the viewport, mask and pool shrink back. Fires `reels:removed`. |
| `addRows` | `(count: number, options?: AddRowsOptions) => void` | Grow every reel by `count` rows below the last one, at its cell size; the viewport, mask and pool grow with it. `options.cells` is what the new rows show, one array per reel (default random). Between `expand()` steps it goes in `onStepLanded`. Not on MultiWays, where a reel's rows are its shape. Fires `rows:added`. |
| `removeRows` | `(count?: number) => void` | Remove the last `count` rows from every reel; without `count`, every row `addRows()` added, a no-op when there are none. Pins on removed rows expire (`'explicit'`). A big symbol that no longer fits the shorter strip is replaced with random symbols. Fires `rows:removed`. |
| `setColumn` | `(reel: number, column: ColumnTarget, options?: SetColumnOptions) => void` | Show `column` on one reel at rest: it shows `column.visible.length` cells. `options.height` says what gives. `'grow'`, the default, keeps the cell size, so the reel grows or shrinks and the board re-anchors around it (with the default `reelAnchor` of `'center'` it grows both ways). `'keep'` keeps the reel's height and resizes its cells to share it. On MultiWays `'keep'` is the default and the only mode, within `[minCells, maxCells]`. Big symbols get their whole block, as in a landing. A pinned cell has to keep its pinned symbol. Only the cells that change are replaced; every other symbol keeps its instance and animation. Fires `column:set`. |
| `splitSymbol` | `(reel: number, cell: number, ids: string[], options?: SetColumnOptions) => { reelIndex, from, count }` | Split the symbol covering `(reel, cell)`, any symbol one reel wide in full view (a 1x1 or a stack), into `ids`, one per cell. The cells above and below keep their symbols, and a pin below rides down with its symbol. A pinned symbol does not split, and a big symbol in `ids` has to end inside them. `options.height` works as in `setColumn()`: `'grow'` adds the difference to the reel, `'keep'` shrinks its cells. Returns where the new cells are. Implemented through `setColumn()`. |
| `resetColumns` | `() => void` | Every reel back to the cells it was built or added with, at their size, keeping its top cells. This undoes `setColumn()`, `splitSymbol()` and `addRows()`. A pin past a reel's cells expires, as on `removeRows()`. A no-op when no reel changed. Not on MultiWays. |
| `isExpanding` | `boolean` (getter) | `true` from `expand:start` on: the `spin:*` events a step fires belong to the expansion, not a new round. `false` again by `expand:complete` and `expand:end`, so a listener there can start the next round. |
| `expand` | `(options: ExpandOptions) => Promise<ExpandResult>` | Grow the board by `columns` (one `ColumnTarget` per reel to add; the server decides how many), `step` reels at a time (a number, default `1`, or a function of the step): add them, spin only them, land them, repeat. Awaits `onStepAdded(step)` before each step spins and `onStepLanded(step)` after it lands. `anticipation` teases a step's reels (`true`, `AnticipationOptions`, or a function per step). Aborting `signal` fast-forwards: everything still to come lands in one step. The steps are one round: pin turns are not spent per step, a skip press speeds up the rest once (the fastest profile; in cascade mode the later steps land at once), a press between steps carries to the next one, and delays stagger by place in the step. MultiWays reels take their shape from `visible.length`; a big symbol widens the step it would straddle. Columns, symbol ids, shapes, blocks and an `anticipation` object are validated before the first reel is added. |

`addReels`, `removeReels` and `expand` throw while the reels spin, a nudge runs, or `expand()` runs; `spin()` throws while `expand()` runs. `addRows`, `removeRows`, `setColumn`, `splitSymbol` and `resetColumns` throw while the reels spin or a nudge runs, and inside an expansion they are allowed only between steps (in `onStepLanded`). `setColumn` and `splitSymbol` also throw on a reel that a big symbol wider than one reel covers, because the reels a block spans share one geometry.

| Type | Shape | Notes |
|---|---|---|
| `ExpandStep` | `{ index, from, count, reelCount, fastForward }` | One step: the reels `from .. from + count - 1` it added, the board size after it, and whether it is the fast-forward. |
| `ExpandStepLanded` | `ExpandStep & { result: SpinResult }` | The step after its reels landed; `result.symbols` is the whole board. |
| `ExpandResult` | `{ from, reelCount, steps, symbols, wasSkipped }` | What `expand()` resolves with. |

## Random symbol pools

| Accessor | Description |
|---|---|
| `randomSymbols` | `RandomSymbolControl`. `{ set(pool, scope?), clear(), weights(scope?) }`. Narrows what the engine may draw for cells you did not name: globally or per reel, for the whole strip, for both buffer ends, or for one end on its own. |

```ts
// Nothing collectible may sit half-visible above or below the grid.
reelSet.randomSymbols.set({ exclude: ['COIN'] }, { slots: 'buffer' });

// ...or just above it. `bufferStart` is the smaller main coordinate (above
// when vertical, left when horizontal), the same end ColumnTarget names.
reelSet.randomSymbols.set({ exclude: ['COIN'] }, { slots: 'bufferStart' });

// Reel 2 runs hot on wilds for the feature, then back to normal.
reelSet.randomSymbols.set({ weights: { WILD: 40 } }, { reel: 2 });
reelSet.randomSymbols.set(null, { reel: 2 });
```

A pool governs the random draw only. An explicit `setResult` target always
wins. Layers resolve in this order, widest first: base weights, global
spinning, per-reel spinning, global buffer, per-reel buffer, global side,
per-reel side. Weights override per id, exclusions accumulate, and a narrower
layer can never re-admit what a wider one banned. `weights({ slots: 'buffer' })`
reports what both sides inherit; ask for one side to see exactly what it draws
from. The build-time equivalent is `builder.randomSymbols(pool, scope)`.

## Events

`reelSet.events` is a typed `EventEmitter<ReelSetEvents>`. See the [events reference](/reference/api-events/) for the full surface. Per-reel events live on `reel.events`.

```ts
reelSet.events.on('spin:complete', (r) => console.log(r.symbols));
reelSet.events.on('cascade:dropIn:symbol', squishOnLand);
reelSet.events.off('cascade:dropIn:symbol', squishOnLand); // unsubscribe
```

## Example: minimal cascade slot

```ts
import { ReelSetBuilder, SpriteSymbol } from 'pixi-reels';

const reelSet = new ReelSetBuilder()
  .reels(6).visibleCells(5).symbolSize(95, 95).symbolGap(5, 5)
  .symbols((r) => { /* register your sprites */ })
  .tumble({
    fall:   { duration: 280, ease: 'sine.in',       cellStagger: 40 },
    dropIn: { duration: 480, ease: 'back.out(1.6)', cellStagger: 50 },
  })
  .ticker(app.ticker)
  .build();
app.stage.addChild(reelSet);

const spinDone = reelSet.spin();
reelSet.setResult(await server.spin());
await spinDone;

await reelSet.runCascade({
  detectWinners: detectWins,
  nextGrid:      (_, winners) => server.cascade(winners),
});
```
