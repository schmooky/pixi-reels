## The basic board

<a id="hold-and-win"></a>

### Respin round

Coins lock where they land and the free cells respin until the grid fills or the respins run out. The board runs the round. The coin values belong to your game.

### Feature mode by middleware

This one does not use the board. It switches a plain `ReelSet` into a bonus mode at runtime by adding a frame middleware, and back by removing it, with no rebuild. In the bonus mode the middleware turns some visible cells into WILD.

## Pacing the wave

<a id="hold-and-win-anticipation"></a>

### Last-cell anticipation

The `anticipateWhen` builder option slows the last spinning cell to a tension profile, for the moment when one more coin would fill the board.

<RecipeDemo code="hold-and-win-anticipation" height={440} />

<a id="hold-and-win-skip"></a>

### Skip

`board.skip()` puts each spinning cell at its landed position and fires `feature:skip`. `feature:end` is still the one event that says the feature is over.

<RecipeDemo code="hold-and-win-skip" height={420} />

<a id="hold-and-win-quicken"></a>

### Quicken

`board.skip({ mode: 'quicken' })` lands each spinning cell through its stop instead of placing it. The board's stagger lives in each cell's minimum spin time, so dropping it lands the whole wave together, and each cell still spins its symbol in and bounces. Add `speed: 'turbo'` to land the wave on the turbo profile, or call `HoldAndWinBuilder.skipMode('quicken')` to make quicken the default. `feature:skip` reports the count and the mode, and the landing events fire as usual.

<RecipeDemo code="hold-and-win-quicken" height={320} />

<a id="hold-and-win-clover-speeds"></a>

### One speed switch

`speeds(normal, turbo, superTurbo)` registers each profile in each cell's `SpeedManager`, and `board.setSpeed(name)` switches them all at once, the board's version of `reelSet.setSpeed()`. A wave already in flight finishes on its own profile, so a turbo press in the middle of a wave is `setSpeed` plus `skip()`. The landing wave steps by each profile's `stopDelay` (70, 25 and 0 ms here), so it tightens as the speed goes up and lands in one go on superTurbo, without a stagger function.

<RecipeDemo code="hold-and-win-clover-speeds" height={420} />

<a id="hold-and-win-cell-control"></a>

### One cell at a time

`board.reelAt(cell)` returns the cell's own 1x1 `ReelSet`. You can start it, slam-stop it and read the symbol in it without touching the other cells. Use this when a feature needs a cell to move outside the normal wave.

<RecipeDemo code="hold-and-win-cell-control" height={300} />

Each cell has its own mask. `cellMask` takes a function that is called once per cell with its column, its row and the board size, and returns that cell's mask strategy. ## Travel direction

<a id="hold-and-win-horizontal-lock"></a>

### Sideways

The round on `.axis('horizontal')`. Each cell is its own 1x1 `ReelSet`, so the axis only decides which edge a coin scrolls in from. The board still lays out columns by rows, and a lock still claims one cell.

Don't build this on a plain `ReelSet` with `.orientation('horizontal')`. There a reel is a whole row, so the row moves as one strip across the gaps and past the cells that should be locked.

<RecipeDemo code="hold-and-win-horizontal-lock" height={340} />

<a id="hold-and-win-reverse-respin"></a>

### Upward

The round on `.axis('vertical', 'reverse')`. It also shows the hold that goes with it. `respin()` spins `board.freeCells` and nothing else, and `respin:start` reports which cells are in flight.

On a `ReelSet` the equivalent is `spin({ holdReels })`, which holds a whole reel. A board has no `holdReels` because Hold & Win holds single cells.

<RecipeDemo code="hold-and-win-reverse-respin" height={340} />

## Draw order and dimming

<a id="hold-and-win-clover-cell-order"></a>

### Cell draw order

Each cell is its own reel set, so the clovers the engine lifts above the cells at rest share one layer, drawn in attach order. That order is column by column, which lets the next column's clover cover a lower clover's glow. `cellZIndex` sorts the layer by whatever the board returns, here lower rows in front and the capsule above everything, and the board asks again on each place and landing.

<RecipeDemo code="hold-and-win-clover-cell-order" height={400} />

<a id="hold-and-win-clover-lift"></a>

### Lift one cell

`cellZIndex` is the order at rest, and the board asks for it again on each place and landing. A clover that must stay on top while it upgrades can't get there by returning a bigger number, because the next landing overwrites it during the animation. `board.lift(cell)` raises the cell on a separate channel and returns a release function. The refresh keeps running underneath without touching the lifted cell, and the release puts the cell back without recomputing anything.

<RecipeDemo code="hold-and-win-clover-lift" height={400} />

<a id="hold-and-win-clover-lift-dim"></a>

### Lift and dim

`board.dim({ except })` goes with `lift()`. The dim draws above the clovers and below anything lifted, so a lifted cell stays in front of it whether or not it is in `except`. A dim covers cells, not symbol ids, so this collect works out which cells hold the gold clovers it is about to sweep and spares them. The money stays bright and the blanks go dark. The dim fades in and out over `fade` ms off the board's own ticker, and `fade: 0` cuts.

<RecipeDemo code="hold-and-win-clover-lift-dim" height={400} />

<a id="hold-and-win-clover-dim-symbols"></a>

### Dim the cell or the art

There are two ways to push a board back. `dim()` lays a rectangle over each cell, so the clover goes dark along with the tile it sits in. `dimSymbols()` tints each symbol towards black instead, so the art sinks and the board stays lit. The same sweep runs twice in the demo, once with each. `amount` sets the strength on both, and both fade over `fade`.

This is a board method rather than a few lines of `gsap.to` because a dimmed cell that swaps its symbol has to keep its dim, and the symbol that left has to lose its tint before the pool gives it to another cell.

<RecipeDemo code="hold-and-win-clover-dim-symbols" height={400} />

<a id="hold-and-win-clover-dim-one-cell"></a>

### Dimming one cell up close

One cell, scaled up, holding a fruit instead of a clover so the cell's background shows all around the symbol. The blue plate is drawn by `cellChrome()` on the board, not by a symbol, so `dimSymbols()` never touches it. `amount` steps through 0.3, 0.6 and 0.9 and the plate stays the same. Then the same 0.6 through `dim()` takes the whole cell down.

In the last step the cell is swapped to the empty id. There is no art left to dim, so `dimSymbols()` changes nothing, neither the symbol that has gone nor the plate.

Watch for this on a real board. If your blank tile is a registered symbol, as the dark tile is in the clover demos (the `empty` id), it is art and `dimSymbols()` dims it too. Draw anything that must stay lit in `cellChrome()`, or name its cell in `except`.

<RecipeDemo code="hold-and-win-clover-dim-one-cell" height={400} />
