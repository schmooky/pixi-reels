## Shape the tease: surge, then crawl

The stock tease can only slow down, and the way it slows down is the problem.
It eases `reel.speed` to a fraction of spin speed over the first 35% of the
hold, then sits flat for the other 65%.

Two things follow. **An ease applied to a speed is a step in acceleration:**
`power2.out` puts peak deceleration on the very first frame and decays from
there, so the reel does not so much slow down as get set to a lower speed. And
**there is no way to ask a reel to speed up first** - the phase is called
anticipation but the implementation is deceleration.

`curve` replaces the fixed shape with explicit legs. Speeds are multiples of the
profile's `spinSpeed`, so `2` is a genuine surge and `0.08` is a crawl. Segment
eases default to `power2.inOut`, which ramps the acceleration in *and* out.

```ts
reelSet.setAnticipation([2, 3, 4], {
  stagger: 260,
  curve: [
    { speed: 2,    duration: 240, ease: 'power2.in' },
    { speed: 0.08, duration: 620, ease: 'power3.inOut', hold: 300 },
  ],
});
```

**Gotcha:** `curve` and `slowdown` together throws. `slowdown` is shorthand for
a two-leg curve, so accepting both would mean silently picking one - express the
whole tease in `curve` instead.

The profile's `anticipationDelay` still gates whether the tease runs at all (so
Turbo still needs a `duration` override to tease), but the curve's own segment
durations set the length.

<a id="anticipation-curve-per-reel"></a>

## A different curve per reel

`slowdown` escalates by interpolating two numbers across the tease sequence. Two
curves of different lengths have no meaningful midpoint, so `curve` takes a
function instead:

```ts
curve: (order, total) => AnticipationSegment[]
```

`order` is the reel's place in the anticipation set, **not** its reel index - so
`setAnticipation([4, 2, 3], ...)` hands `order: 0` to reel 4. That is the same
ordering `slowdown` interpolates over and `protect: 'stepwise'` releases in.

<a id="anticipation-cells"></a>

## Tease for N symbols, not N milliseconds

`duration` is a time budget, so how far a reel actually moves during a tease
depends on its speed. If the tease is choreographed around symbols going past
the window - "three more and then it lands" - time is the wrong anchor.

`cells: n` ends the tease once the reel has travelled n symbol pitches, read off
a monotonic odometer (`reel.travelledCells`) that survives the snap at the end
of every spin.

Time is right when the tease is cut to an audio bed; travel is right when it is
cut to symbols passing the window. Neither is the default for the other.

**The anchor applies to the final leg of a curve.** Earlier legs play in full,
and the last one holds until the target is met instead of for its scripted
`hold`. Measuring from the start of the tease instead would let a fast opening
segment burn the whole travel budget and silently delete every leg after it -
add `cells: 2` to a surge-then-crawl curve and you would never see the crawl.

`cells` takes the same function-of-tease-order form as `curve`, so a sweep can
run each successive reel further than the last:

```ts
reelSet.setAnticipation([2, 3, 4], {
  curve: [{ speed: 0.25, duration: 300 }],
  cells: (order) => 2 + order,   // 2, 3, then 4 symbols
});
```

**Gotcha:** `duration` stays as the backstop on that final leg. A reel that
comes to rest can never reach a travel target, and a tease that never ends is a
hung spin - so the tease runs for at most the curve plus `duration`. A final leg
that sits at speed `0` can never reach the target at all, and says so on the
notice channel.

<a id="anticipation-drive"></a>

## The gas pedal: bounded acceleration

Everything above still shapes the tease with an ease, and an ease only shapes
the one transition it was written for.

`motionModel('drive', { accel, decel, jerk })` bounds acceleration instead.
Phases stop tweening `reel.speed` and start assigning `reel.targetSpeed`;
`Reel.update` walks the speed toward it, never faster than the bounds allow. The
reel can only change speed so fast, whatever it is asked for, and every
transition inherits that - including ones nobody authored. Add `jerk` and the
acceleration itself ramps: the pedal goes down over time rather than being
stamped.

It also makes interruption free. A skip press, a mid-tease retarget or a
`setSpeed` mid-spin is one target assignment, and the motion stays continuous by
construction - there is no timeline to kill and no leftover speed to reconcile.

```ts
builder.motionModel('drive', {
  accelFrames: 20,   // frames from rest to the ACTIVE profile's full speed
  decelFrames: 34,   // leans into its stops
  jerkFrames: 260,   // the S-curve; omit for a snappier response
})
```

The bounds are **profile-relative**, and that matters as soon as a game has more
than one speed. The shipped presets run `spinSpeed` 30 / 50 / 80, so a single
absolute `px/frame^2` bound tuned for Normal makes SuperTurbo take 53 frames to
reach speed where Normal takes 20 - a turbo that starts *slower* than normal.
`accelFrames` re-resolves against whichever profile is running, so the feel
holds across all three.

The absolute form is still accepted for a single-profile game:

```ts
builder.motionModel('drive', { accel: 1.5, decel: 0.9, jerk: 0.12 })
```

Units there are px/frame^2 at 60fps, matching `spinSpeed`'s px/frame. Mixing the
two forms throws.

If a segment asks for a speed the drive cannot reach inside that segment's
duration, the leg simply ends where it got to and the next retarget hides it -
so the engine says so once on the notice channel, with the acceleration that
would have been needed.

**Opt-in, at build time only.** The default `'tween'` model is byte-for-byte
unchanged, and there is no runtime toggle: handing `reel.speed` to a second
owner while a phase is mid-tween is the failure this design avoids.

Two moments stay instant under a drive, and both are deliberate. **Landing**
halts the reel dead so it can snap to grid and bounce - the bounce tween is what
covers it. **A skip press** means now. Both are identical in the tween model, so
neither is the drive's to smooth.

## Driving tease audio

`anticipation:reel` (`{ reelIndex, order, total }`) and `anticipation:reelEnd`
are the discrete bookends - use them to start and stop a tension loop.

Between them, `anticipation:segment` (`{ reelIndex, index, total, speed,
targetSpeed }`) fires once per leg of a `curve`, in order. That is what lets a
surge get a different sound from the crawl that follows it without polling the
speed and inferring where one ended:

```ts
reelSet.events.on('anticipation:segment', ({ index, speed }) => {
  if (speed > 1) sfx.play('tease-surge');
  else if (index > 0) sfx.play('tease-crawl');
});
```

For a pitch ramp that tracks the actual slow-down rather than just its start and
end, sample `reelSet.reels[i].speedNormalized` from your own ticker. It is live
speed over the profile's spin speed: `1` at full blur, `0` at rest, negative
during the start-up pull, and above `1` during a surge segment.

## Skip that cannot hide the tease

The same long tease, but the first press only lands the reels AROUND it. `protect: 'once'` guarantees the two scatters are on screen and the build-up is visibly under way before a second press can end it.

**Gotcha:** call `setAnticipation` BEFORE `setResult`. A press in the pre-result window is queued by `requestSkip()` and fires the instant the result arrives, so the tease has to be registered by then or there is nothing to protect.

<RecipeDemo code="protected-anticipation" />

`protect: 'stepwise'` walks it forward one reel per press instead of ending it in one go. That, partial slams, per-reel spin floors, and why a protected tease beats a slower skip are all on [Skip & slam](/recipes/skip/).
