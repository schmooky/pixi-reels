## Horizontal banner

A one-reel strip that scrolls sideways, such as a banner showing which symbols pay this round. It is `.orientation('horizontal')` on the normal builder, with the same spin lifecycle, events and speed profiles as a vertical set.

### Every reel

`.direction('reverse')` makes every reel spin upward. The spin, the events and the landing bounce are the same, run the other way.

### Direction per reel

`.directionPerReel([...])` sets each reel's direction on its own. Here odd reels spin up and even reels spin down. Each reel still lands the exact result, because it feeds new symbols from its own edge.

## Sideways with mixed direction

Orientation is set for the whole set at `build()`, and direction is set per reel, so the two combine. Here the strips run sideways, rows 0 and 2 scroll right, and rows 1 and 3 scroll left.

A big symbol wider than one reel (`size.reels > 1`) cannot be combined with mixed per-reel directions. A block assumes every reel it covers feeds from the same edge and would split mid-spin, so `build()` throws. A `directionPerReel` array with the same value throughout is fine.

## Banner in a ways win

A horizontal banner above a 5x3 ways set. The banner acts as a sixth reel: a wild in the banner cell above a reel makes that reel count toward the way. These are two `ReelSet`s in one container. The engine spins and lands both. The recipe evaluates the ways and spotlights the cells, because pixi-reels never computes wins.

## Reading the axis

Each reel has `reel.axis`, with `orientation`, `direction`, `polarity`, `mainProp`, `crossProp` and `feedEdge`. `axis.toScreen(0, axis.polarity)` turns one step of travel into a screen vector, so the arrows in the demo are drawn with no orientation check. The same code points down on a vertical forward reel and left on a horizontal reverse one.

`feedEdge` is the side new symbols arrive from. It is derived from `polarity`: `'start'` for forward, `'end'` for reverse. Read it when you need it instead of tracking it next to `direction`.
