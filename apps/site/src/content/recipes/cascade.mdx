## Removing winners

Each cascade step runs in a fixed order: present the win, destroy the winning symbols, refill the holes. Work out the winners from your match logic. Diffing the grid before and after does not work, because survivors slide past the cleared cells and a diff reads them as changed.

### Present the win first

Two winning combinations share reel 2. `runCascade` hands them to a `WinPresenter` through its `presentWinners` hook, which shows each one in turn before the winners explode and the refill drops.

### Two-stage refill

`refill({ mode: 'gravity-then-drop' })` splits the refill in two. Survivors slide down first, the engine holds for `gravityHoldMs`, then the new symbols drop in. Put a multiplier or a mascot beat in the hold. The second canvas drops the reels one after another instead of in a wave, with a longer hold.

## Gravity and orientation

By default a reel drains toward the edge it travels toward and refills from the other one. Gravity also decides the server contract. Survivors must be packed against the edge they drain through, and the engine animates the grid you send as it is. It never reorders it.

<a id="cascade-horizontal-tumble"></a>
<a id="cascade-sideways"></a>

### Sideways

The same tumble on `.orientation('horizontal')`. Reels are screen rows, the strip travels along X, and `tumble({ gravity })` stays on its default `'auto'`. Under forward gravity, `nextGrid` returns `[...fresh, ...survivors]`.

<RecipeDemo code="cascade-horizontal-tumble" height={300} />

<a id="cascade-drain-upward"></a>
<a id="drain-upward-gravity-follows-travel"></a>

### Upward

A `.direction('reverse')` set with no `gravity` key. Gravity follows travel, so the top cell falls and lands first and the column empties upward. The survivors now pack against the top, so `nextGrid` returns `[...survivors, ...fresh]`. If you reverse the reels and keep the old grid order, the board looks scrambled.

<RecipeDemo code="cascade-drain-upward" height={300} />

<a id="cascade-reverse-gravity"></a>
<a id="spin-up-drop-down-explicit-gravity"></a>

### Spin up, settle down

Reels built `.direction('reverse')` roll upward, and `tumble({ gravity: 'forward' })` makes the tumble settle downward anyway. Set `gravity` only when you want travel and settling to disagree.

The cell stagger follows gravity too. `cellOrder` defaults to `'auto'`, which starts at the end symbols leave through. Here the bottom cell still goes first; without the `gravity` override the top cell would lead. Pass `'endFirst'` or `'startFirst'` to fix the starting end whatever the gravity.
