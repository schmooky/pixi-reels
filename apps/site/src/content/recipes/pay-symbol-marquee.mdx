Both strips start **paused**. Press Run to spin them up; press it again to stop
them dead in place — that toggle is just `start()` / `stop()`. Each spin-up
re-rolls the paying set. There is **no spin lifecycle, no win lines, no grid**
here — this is the banner *above* the reels, not the reels themselves.

## Spin and stop it

`HorizontalReel` has no start/spin/stop *phases* like the vertical reel — it's a
marquee, so "spin" and "stop" are just motion on/off:

```ts
const strip = new HorizontalReelBuilder()
  /* … */
  .autoStart(false)   // build it paused (default is true — runs immediately)
  .build();

strip.start();        // spin — begin / resume motion (idempotent)
strip.stop();         // stop — freeze in place (idempotent)
strip.isRunning;      // current state, e.g. to drive a toggle button
```

This recipe's button is exactly that toggle:

```ts
onSpin: () => {
  if (strip.isRunning) strip.stop();
  else { strip.setContent(rollPayingSet()); strip.start(); }
};
```

## A horizontal reel is its own small mechanism

The engine's `Reel` wraps symbols on the **Y** axis and bakes that assumption in
throughout (`ReelMotion`, the stop sequencer, buffer rows). A sideways banner is
a different axis, so `HorizontalReel` is a focused mechanism of its own — one
row, no spin lifecycle — built on the same shared primitives (the symbol pool,
`TickerRef`, the typed `EventEmitter`) rather than a rotated reel.

```ts
const strip = new HorizontalReelBuilder()
  .visibleCount(5).cellSize(64, 64, { gap: 8 })
  .direction('rtl').scroll(1.3)
  .symbols((r) => { for (const c of CARD_DECK) r.register(c.id, CardSymbol, c); })
  .content(payingIds)          // the looping "these pay" sequence
  .ticker(app.ticker)
  .build();
app.stage.addChild(strip.container);
```

## Two motions: scroll and cascade

| Mode | Call | Feel |
|---|---|---|
| `scroll` | `.scroll(pxPerFrame)` | smooth, continuous marquee (default) |
| `cascade` | `.cascade({ interval, duration })` | hold, ease one cell over, repeat — the tumble reveal on its side |

Both honour `direction`: `rtl` feeds from the right, `ltr` from the left.

## The live surface

| Member | Use |
|---|---|
| `setContent(ids)` | swap the paying set for the next round — new symbols fade in as the strip recycles |
| `setDirection('ltr' \| 'rtl')` | flip travel live; the feed edge swaps |
| `start()` / `stop()` | freeze / resume the strip |
| `symbolAt(slot)` | the live `ReelSymbol` in visible slot `slot`, left→right |
| `events` | `symbol:entered ({ id, edge })` as each new tile wraps in; `cascade:step` per step |
| `destroy()` | drops the ticker subscription and pooled instances |
